Build Order

  1. เพิ่ม HTTP Request Defaults แล้วตั้ง host/port
  2. เพิ่ม User Defined Variables สำหรับค่า default ที่จะ reuse ทั้ง test plan
  3. เพิ่ม Thread Group
  4. เพิ่ม Transaction Controller และเปิด Generate parent sample
  5. เพิ่ม HTTP requests ตามลำดับ flow
  6. เพิ่ม HTTP Header Manager สำหรับ POST
  7. เพิ่ม JSON Extractor ใต้ /demo/context และ /demo/checkout
  8. เพิ่ม View Results Tree เพื่อ debug
  9. เพิ่ม Summary Report หรือ Aggregate Report

Extractor And Variable Flow

  • /demo/context -> extract demoCartId, demoShopperId, demoProductId, demoSearchTerm
  • /demo/checkout -> extract demoOrderId
  • If Controller -> เช็ก ${demoOrderId} ก่อนยิง /demo/order/status

Recommended HTTP Header Structure

อย่าใส่ทุก header ไว้ระดับบนสุดถ้าไม่ได้ใช้กับทุก request จริง ให้แยก header ตามขอบเขตการใช้งาน จะดูแลง่ายกว่า
HeaderSuggested ValueWhere To Put ItUse Case
Accept${acceptHeader} หรือ application/jsonTest Plan หรือ Thread Groupใช้กับ request ส่วนใหญ่ในระบบนี้
Accept-Language${demoLanguage} หรือ en/thTest Plan หรือ Thread Groupใช้สลับภาษา demo ทั้ง flow
Content-Type${contentType} หรือ application/jsonเฉพาะ POST /demo/cart/add, POST /demo/checkout, POST /submit-one, POST /submit-twoหลีกเลี่ยงการใส่ผิดกับ GET ทั้งหมด
x-access-token${demoAuthToken}เฉพาะ sampler /protectedใช้ทดสอบ auth flow
AuthorizationBearer ${demoAuthToken}เฉพาะ sampler /protectedใช้แทน x-access-token ได้

Practical Rule Of Thumb

  • ค่า endpoint infrastructure เช่น protocol, host, port ให้เก็บใน defaults เสมอ
  • ค่าทางธุรกิจที่ใช้ซ้ำ เช่น search term, product id, cart id ให้เก็บใน variables
  • header ที่ใช้ทุก request เช่น Accept ให้ไว้ระดับบน
  • header อย่าง Accept-Language เหมาะมากกับการวางไว้ระดับบนถ้าจะให้ทั้ง flow ใช้ภาษาเดียวกัน
  • header ที่ใช้เฉพาะบาง request เช่น Content-Type หรือ token ให้ไว้ใกล้ sampler นั้น
  • ค่าอย่าง demoOrderId ให้เริ่มด้วย placeholder เช่น NOT_SET แล้วให้ extractor มาแทนภายหลัง
