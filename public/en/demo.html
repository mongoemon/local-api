Read The Result

After a test run, do not only check whether requests passed or failed. Look at 4 things together: transaction time, error rate, throughput, and traffic mix.

What To Open In JMeter

ComponentUse It To CheckWhy It Matters
View Results TreeThe actual response of each individual requestUse for debugging when a request fails, a variable is not extracted correctly, or the body/headers are wrong
Summary ReportAverage, min, max, error %, throughputUse for a quick overall view of whether the test run met the basic SLA threshold
Aggregate ReportMedian, 90%, 95%, 99%Use to make SLA decisions — percentiles matter more than averages
Transaction Controller parent sampleTotal time for the entire flowUse to answer whether the complete user journey is fast enough
Backend Listener (if present)Continuous metrics during long runsUse to detect drift in load or endurance tests

What To Look At First

  1. Check Error % first — if errors are still high, the test is not passing regardless of latency numbers
  2. Check 90%, 95%, and 99% in the Aggregate Report
  3. Check the parent sample of the Transaction Controller to see how long the full flow took
  4. Check the Throughput Controller to see if the cart flow sample count is close to the configured percentage
  5. If an If Controller is present, verify that order status is only called when a real orderId exists
For example SLA statements, test type decisions, and run order — see Test Types.

Proof Of Concept You Can Copy And Paste

If you need a quick proof of concept, copy the statement, structure, and starting values below to get started immediately.

POC SLA Statement

Customer SLA Statement
"Under normal business load, the demo browse flow must complete with p95 below 800 ms,
and the Add And Checkout transaction must complete with p95 below 1500 ms,
with error rate below 1%.
Around 40% of browse sessions are expected to continue to cart and checkout."

POC Test Type Decision

Recommended test type: Load Test

Reason
- The statement talks about normal business load
- It includes a browse flow target
- It includes a checkout transaction target
- It includes a traffic mix target of 40%

POC JMeter Structure

Test Plan
├─ HTTP Request Defaults
├─ Thread Group
│  ├─ Transaction Controller - Browse Flow
│  │  ├─ HTTP Request - demo context
│  │  │  └─ JSON Extractor
│  │  ├─ HTTP Request - demo dashboard
│  │  ├─ HTTP Request - demo search
│  │  └─ HTTP Request - product details
│  ├─ Throughput Controller - Cart Flow (40%)
│  │  └─ Transaction Controller - Add And Checkout
│  │     ├─ HTTP Request - add to cart
│  │     └─ HTTP Request - checkout
│  │        └─ JSON Extractor
│  ├─ If Controller - if demoOrderId exists
│  │  └─ HTTP Request - order status
│  ├─ Summary Report
│  └─ Aggregate Report
└─ View Results Tree

POC Starting Values

HTTP Request Defaults
- Protocol: http
- Server: localhost
- Port: 3001

Thread Group
- Number of Threads: 10
- Ramp-Up Period: 5
- Loop Count: 20

Throughput Controller
- Style: Percent Executions
- Percent: 40

Transaction Controller
- Generate parent sample: true

POC JSON Extractor Setup

Under /demo/context
- demoCartId = $.cartId
- demoShopperId = $.shopperId
- demoProductId = $.recommendedProductId
- demoSearchTerm = $.searchTerm

Under /demo/checkout
- demoOrderId = $.orderId

{
  "cartId": "${demoCartId}",
  "productId": "${demoProductId}",
  "quantity": 1

POST /demo/checkout
{
  "cartId": "${demoCartId}",

}

POC Pass Criteria

Pass if:
- Browse Flow p95 < 800 ms
- Add And Checkout p95 < 1500 ms
- Error rate < 1%
- Cart Flow sample count is around 40% of Browse Flow sample count

POC Example Conclusion

Example result
- Browse Flow p95 = 640 ms
- Add And Checkout p95 = 1280 ms
- Error rate = 0.4%
- Browse Flow count = 1000
- Cart Flow count = 401

Conclusion
- Browse Flow passed
- Add And Checkout passed
- Error rate passed
- Traffic mix passed
- This proof of concept meets the sample customer SLA
