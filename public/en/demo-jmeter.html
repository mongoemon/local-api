Build Order

  1. Add HTTP Request Defaults and set the host and port
  2. Add User Defined Variables for default values that will be reused across the test plan
  3. Add a Thread Group
  4. Add a Transaction Controller and enable Generate parent sample
  5. Add HTTP requests in the order of the flow
  6. Add an HTTP Header Manager for POST requests
  7. Add a JSON Extractor under /demo/context and /demo/checkout
  8. Add a View Results Tree for debugging
  9. Add a Summary Report or Aggregate Report

Important Controllers

ControllerUse ForExample
Transaction ControllerMeasure the total elapsed time of a flowBrowse Flow, Add And Checkout
Throughput ControllerControl what percentage of iterations execute a given part of the flowRun cart flow 40% of the time
If ControllerExecute a step only when a required variable is presentRun order status only when ${demoOrderId} is set

Extractor And Variable Flow

  • /demo/context -> extract demoCartId, demoShopperId, demoProductId, demoSearchTerm
  • /demo/checkout -> extract demoOrderId

Recommended HTTP Header Structure

Do not place every header at the top level if it is not actually used by every request. Scope each header to its appropriate level — this makes the plan easier to maintain.
HeaderSuggested ValueWhere To Put ItUse Case
Accept${acceptHeader} or application/jsonTest Plan or Thread GroupApplies to most requests in this system
Accept-Language${demoLanguage} or en/thTest Plan or Thread GroupSwitches the demo language across the entire flow
Content-Type${contentType} or application/jsonOnly on POST /demo/cart/add, POST /demo/checkout, POST /submit-one, POST /submit-twoAvoids incorrectly attaching a Content-Type to GET requests
x-access-token${demoAuthToken}Only on the /protected samplerUsed to test the auth flow
AuthorizationBearer ${demoAuthToken}Only on the /protected samplerAlternative to x-access-token

Practical Rule Of Thumb

  • Infrastructure values such as protocol, host, and port always belong in the defaults
  • Business values reused across requests, such as search term, product ID, and cart ID, belong in variables
  • Headers used by every request, such as Accept, should be placed at the top level
  • Headers like Accept-Language are well-suited to the top level when the entire flow should use the same language
  • Headers scoped to specific requests, such as Content-Type or auth tokens, should be placed close to the relevant sampler
  • Values like demoOrderId should start with a placeholder such as NOT_SET and be overridden by an extractor later in the flow
