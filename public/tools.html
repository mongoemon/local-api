Performance Testing Tools In Real Industry

หน้านี้รวบรวมเครื่องมือที่ใช้จริงในวงการ performance testing จัดกลุ่มตามบทบาท พร้อมอธิบายว่าแต่ละตัวใช้ทำอะไร และทำไมองค์กรถึงเลือกใช้

Tool Categories

  1. Load Generation — เครื่องมือสร้าง traffic เพื่อทดสอบ
  2. Monitoring & Metrics — เก็บและดู metric ระหว่างและหลังทดสอบ
  3. Visualization & Dashboards — แสดงผล metric เป็นกราฟ
  4. APM — Application Performance Monitoring — ติดตาม performance ระดับ code
  5. Cloud Load Testing — รัน test แบบกระจายหลายภูมิภาค
  6. API Testing & Exploration — ทดสอบ API แบบ manual และ automated
  7. Common Tool Stacks — ชุดเครื่องมือที่ใช้ร่วมกันในองค์กรจริง
  8. Comparison Table — เปรียบเทียบโดยตรง
  9. How To Choose — เลือกอะไรให้กับโปรเจกต์ตัวเอง
1. Load Generation Tools

เครื่องมือกลุ่มนี้ทำหน้าที่สร้าง traffic จำลองผู้ใช้จริง เพื่อวัด response time, throughput และ error rate

Apache JMeter

Open Source Free ภาษา: Java GUI + XML config (.jmx) Platform: Desktop (Windows / Mac / Linux)

ใช้ทำอะไร: สร้าง test plan ผ่าน GUI, ยิง HTTP request, จำลอง concurrent users, สร้าง report

ทำไมองค์กรเลือกใช้:

  • มีมานานกว่า 25 ปี มี community ขนาดใหญ่และมี plugin ครอบคลุม
  • GUI ใช้งานได้โดยไม่ต้องเขียน code — เหมาะกับ QA ที่ไม่ถนัดการเขียนโปรแกรม
  • รองรับ protocol หลากหลาย: HTTP, HTTPS, FTP, JDBC, JMS, SOAP, LDAP
  • มี plugin เช่น Concurrency Thread Group, Stepping Thread Group, Backend Listener ที่ติดตั้งเพิ่มได้
  • รัน Non-GUI mode ใน CI/CD ได้ด้วย jmeter -n -t plan.jmx -l results.jtl
  • ใช้งานร่วมกับ BlazeMeter Cloud เพื่อรัน distributed test ได้

จุดอ่อน: ใช้ RAM มาก, GUI ล้าสมัย, test script เป็น XML อ่านยากเมื่อ diff ใน Git

ใช้เมื่อ: ต้องการเครื่องมือฟรี, ทีมไม่ถนัด code, ต้องการ plugin ecosystem ที่กว้าง

k6 (by Grafana Labs)

Open Source Free (k6 Cloud เสียค่าใช้จ่าย) ภาษา: JavaScript (ES6+) Platform: CLI, Docker, CI/CD

ใช้ทำอะไร: เขียน test script เป็น JS, รันจาก terminal, export metric ไป Prometheus/InfluxDB/Grafana

ทำไมองค์กรเลือกใช้:

  • Script เป็น JS จริง — เขียนได้ flexible, เก็บใน Git ได้ดี, review ง่าย
  • ใช้ resource น้อยกว่า JMeter มาก (เขียนใน Go) — รัน virtual user ได้มากกว่าต่อ CPU
  • built-in metrics ออกแบบมาสำหรับ Prometheus/Grafana stack โดยตรง
  • รัน CI/CD ได้ทันทีโดยไม่ต้องติดตั้ง GUI หรือ Java
  • รองรับ Scenarios API — กำหนดหลาย load profile ในไฟล์เดียว
  • ต่อกับ k6 Cloud สำหรับ distributed test และ dashboard online ได้

จุดอ่อน: ไม่มี GUI, ต้องเขียน JS, ไม่รองรับ protocol นอก HTTP ได้กว้างเท่า JMeter

ใช้เมื่อ: ทีม dev/DevOps ที่ถนัด code, ต้องการ CI/CD integration, ใช้ Grafana stack อยู่แล้ว

// ตัวอย่าง k6 script เบื้องต้น
import http from "k6/http";
import { check, sleep } from "k6";

export const options = {
  vus: 20,
  duration: "30s",
};

export default function () {
  const res = http.get("http://localhost:3001/fast");
  check(res, { "status is 200": (r) => r.status === 200 });
  sleep(1);
}

Gatling

Open Source + Enterprise ภาษา: Scala DSL (หรือ Java/Kotlin ใน Gatling 3.7+) Platform: CLI, Maven/Gradle plugin, CI/CD

ใช้ทำอะไร: เขียน test เป็น code (Scala/Java/Kotlin), สร้าง HTML report ที่สวยงามในตัว, simulate realistic user sessions

ทำไมองค์กรเลือกใช้:

  • ใช้ Akka actor model ภายใน — handle concurrent users ได้มากโดยใช้ thread น้อย
  • built-in HTML report แสดง percentile, response time distribution, error timeline โดยไม่ต้องตั้ง Grafana
  • เหมาะกับ Java/Scala shop ที่ developer เขียน test เองได้
  • รัน Maven/Gradle plugin ได้ตรง — CI/CD pipeline ใน Java project ทำง่ายมาก
  • test script ดูแลง่ายใน Git เพราะเป็น code ไม่ใช่ XML

จุดอ่อน: Scala DSL มี learning curve สูง, community เล็กกว่า JMeter และ k6

ใช้เมื่อ: Java/Scala ecosystem, ต้องการ built-in HTML report, developer-written performance test

Locust

Open Source Free ภาษา: Python Platform: CLI, Web UI, Docker, Kubernetes

ใช้ทำอะไร: เขียน test เป็น Python, มี Web UI แบบ real-time, รัน distributed บน Kubernetes ได้

ทำไมองค์กรเลือกใช้:

  • Python อ่านง่าย, ทีม data/backend Python เขียน test ได้เลยโดยไม่ต้องเรียนเครื่องมือใหม่
  • Web UI ดู real-time graph ระหว่างรัน test — ปรับจำนวน user ระหว่างรันได้
  • scale ออกหลาย worker บน Kubernetes ได้ง่ายด้วย distributed mode
  • flexible มาก — เขียน custom logic, authentication flow, stateful session ได้เต็มที่

จุดอ่อน: Python GIL อาจจำกัด throughput ต่อ process — ต้อง distributed เพื่อ load สูง

ใช้เมื่อ: ทีม Python, ต้องการ real-time control, distributed load บน Kubernetes

Artillery

Open Source + Pro ภาษา: YAML config + JavaScript hooks Platform: CLI, CI/CD, AWS Lambda

ใช้ทำอะไร: กำหนด load scenario ด้วย YAML, เขียน custom logic ด้วย JS, รัน serverless load test บน AWS Lambda

ทำไมองค์กรเลือกใช้:

  • YAML config อ่านง่าย — เหมาะกับ DevOps ที่ไม่ถนัดเขียน JS เต็ม ๆ
  • รัน distributed บน AWS Lambda โดยไม่ต้องตั้ง infrastructure เอง (Artillery Pro)
  • built-in support สำหรับ HTTP, WebSocket, Socket.io, gRPC
  • ใช้ node ecosystem ได้ทั้งหมดใน custom hooks

จุดอ่อน: feature ขั้นสูงส่วนใหญ่อยู่ใน Pro tier, community เล็กกว่า JMeter/k6

ใช้เมื่อ: cloud-native team, AWS ecosystem, ต้องการ serverless distributed load

2. Monitoring & Metrics Collection

เครื่องมือกลุ่มนี้เก็บ metric จาก application และ infrastructure ระหว่างและหลังการทดสอบ

Prometheus

Open Source Free ภาษา: Go (server), PromQL (query) Platform: Docker, Kubernetes, bare metal

ใช้ทำอะไร: เก็บ time-series metric โดย scrape จาก endpoint /metrics ของแต่ละ service ทุก N วินาที

ทำไมองค์กรเลือกใช้:

  • เป็น de facto standard ของ metrics collection ใน cloud-native/Kubernetes ecosystem
  • pull-based model — Prometheus ไป scrape service เอง ทำให้ service ไม่ต้องรู้จัก Prometheus
  • PromQL query language ทรงพลัง — คำนวณ rate, percentile, aggregation ได้ทันที
  • มี client library ทุกภาษา — Node.js (prom-client), Go, Java, Python
  • Local API นี้ก็ใช้ prom-client — ดูได้ที่ GET /metrics

ใช้คู่กับ: Grafana (visualization), Alertmanager (alerting), k6 (export metric)

# ตัวอย่าง PromQL — p95 ของ HTTP request duration
histogram_quantile(0.95,
  sum(rate(http_request_duration_seconds_bucket[5m])) by (le, route)
)

InfluxDB

Open Source + Cloud ภาษา: Flux / InfluxQL (query) Platform: Docker, Cloud

ใช้ทำอะไร: time-series database ที่ออกแบบมาเก็บ metric เฉพาะ — เขียน/อ่านเร็วกว่า general-purpose DB มาก

ทำไมองค์กรเลือกใช้:

  • JMeter Backend Listener ส่ง metric ไป InfluxDB ได้ทันทีระหว่างรัน test
  • k6 มี --out influxdb flag สำหรับ export real-time metric
  • เหมาะกับ JMeter + InfluxDB + Grafana stack (stack นิยมมากในองค์กรไทย)

ใช้คู่กับ: JMeter (Backend Listener), k6 (--out influxdb), Grafana

3. Visualization & Dashboards

เครื่องมือกลุ่มนี้แสดง metric เป็นกราฟ dashboard ใช้ดูระหว่างรัน test และวิเคราะห์ผลหลังรัน

Grafana

Open Source + Cloud Platform: Docker, Kubernetes, Grafana Cloud

ใช้ทำอะไร: สร้าง dashboard ดึงข้อมูลจาก Prometheus, InfluxDB, Elasticsearch, Loki และ datasource อื่น ๆ อีกหลายสิบตัว

ทำไมองค์กรเลือกใช้:

  • visualization ทรงพลัง — graph, heatmap, table, stat panel, alert ในที่เดียว
  • มี pre-built dashboard สำหรับ JMeter และ k6 ให้ import ได้ฟรีจาก Grafana.com
  • ดู real-time metric ระหว่างรัน load test — เห็น latency spike ได้ทันที
  • เป็น standard ของ DevOps / SRE team ทั่วโลก ทำให้ทีม ops และ perf test ใช้ tool เดียวกัน
  • ตั้ง alert ส่ง Slack/PagerDuty ได้เมื่อ metric เกิน threshold

ใช้คู่กับ: Prometheus, InfluxDB, Loki (logs), Tempo (traces)

Stack ที่พบบ่อย:

  • JMeter → InfluxDB → Grafana
  • k6 → Prometheus → Grafana
  • Locust → Prometheus → Grafana
4. APM — Application Performance Monitoring

APM ไปลึกกว่า metric — ติดตาม request ระดับ code, trace ข้าม service, หา bottleneck ที่แท้จริงใน production

Datadog

Commercial Paid Platform: SaaS (cloud)

ใช้ทำอะไร: เก็บ metric, log, trace และ RUM (Real User Monitoring) ในที่เดียว พร้อม AI-powered anomaly detection

ทำไมองค์กรเลือกใช้:

  • all-in-one — ไม่ต้องตั้ง Prometheus + Grafana + Loki แยก
  • APM Traces ดู call stack ของแต่ละ request ได้ — เห็นว่า bottleneck อยู่ที่ database query ตัวไหน
  • ต่อกับ JMeter / k6 เพื่อเปรียบ load test metric กับ infra metric ในหน้าเดียว
  • RUM วัด performance จากฝั่ง real browser ของผู้ใช้จริง
  • นิยมในองค์กรขนาดกลาง-ใหญ่ที่ต้องการ support และ SLA จาก vendor

New Relic

Free tier + Paid Platform: SaaS (cloud)

ใช้ทำอะไร: APM, infrastructure monitoring, browser monitoring, synthetic monitoring ในที่เดียว

ทำไมองค์กรเลือกใช้:

  • free tier ค่อนข้างใจกว้าง (100 GB data/month) — เหมาะกับ startup
  • auto-instrumentation สำหรับ Node.js, Java, .NET, Python — ติดตั้ง agent แล้วเห็น trace ทันที
  • NRQL (New Relic Query Language) ใช้ query metric, log, trace ได้ในที่เดียว
  • มี Synthetics — สร้าง test script ที่รันซ้ำตลอดเวลาจาก global locations

Dynatrace

Commercial Paid Platform: SaaS / On-premise

ใช้ทำอะไร: AI-powered full-stack monitoring — automatic root cause analysis, code-level visibility, infrastructure monitoring

ทำไมองค์กรเลือกใช้:

  • Davis AI วิเคราะห์ root cause ให้อัตโนมัติ — ไม่ต้องไล่ดู metric เอง
  • OneAgent ติดตั้งเครื่องเดียว monitor ได้ทุกอย่าง — JVM, containers, network
  • enterprise-grade: นิยมในธนาคาร, telco, รัฐบาล ที่ต้องการ on-premise deployment
  • ต่อกับ JMeter/k6 เพื่อ correlate load test กับ APM trace ได้

OpenTelemetry (OTel)

Open Source Free (standard, ไม่ใช่ tool) Platform: ทุก environment

ใช้ทำอะไร: standard กลางสำหรับ instrumentation — เก็บ traces, metrics, logs ในรูปแบบเดียว ส่งไปยัง backend ใดก็ได้

ทำไมองค์กรเลือกใช้:

  • vendor-neutral — ใช้ OTel แล้วส่ง telemetry ไป Datadog, New Relic, Jaeger, Prometheus ได้โดยไม่ต้องเขียนใหม่
  • เป็น CNCF standard — ทุก cloud provider รองรับ
  • แทนที่ proprietary SDK ของ Datadog/New Relic ได้ — ลด vendor lock-in

ใช้คู่กับ: Jaeger (traces), Prometheus (metrics), Loki (logs), Grafana Tempo

5. Cloud Load Testing Platforms

เมื่อต้องการ load สูงหรือ distributed test จากหลายภูมิภาค จะใช้ platform เหล่านี้แทนการรันบนเครื่องเดียว

BlazeMeter (by Perforce)

Free tier + Paid Platform: SaaS

ใช้ทำอะไร: upload JMeter .jmx file แล้วรันบน cloud infrastructure ได้ทันที พร้อม real-time dashboard และ report

ทำไมองค์กรเลือกใช้:

  • ใช้ JMeter script ที่มีอยู่แล้วได้ทันที — ไม่ต้องเรียน tool ใหม่
  • รัน test จากหลาย region พร้อมกัน — เหมาะกับ global application
  • ไม่ต้องตั้ง infrastructure เอง — เหมาะกับ test ที่ต้องการ load หลักพัน VU
  • มี CI/CD plugin สำหรับ Jenkins, GitHub Actions, Azure DevOps

k6 Cloud (by Grafana Labs)

Free tier + Paid Platform: SaaS

ใช้ทำอะไร: รัน k6 script บน cloud infrastructure, ดู result บน dashboard ออนไลน์, เปรียบเทียบผลระหว่าง test run

ทำไมองค์กรเลือกใช้:

  • ต่อจาก k6 CLI ได้ทันทีด้วย k6 cloud script.js
  • รัน distributed จากหลาย region พร้อม result consolidation อัตโนมัติ
  • trend comparison — เปรียบผล run นี้กับ run ก่อนหน้าได้

Azure Load Testing

Paid (ตาม VUH — Virtual User Hours) Platform: Azure SaaS

ใช้ทำอะไร: managed load testing service บน Azure — upload JMeter script หรือ URL แล้วรันได้ทันที

ทำไมองค์กรเลือกใช้:

  • integrate กับ Azure DevOps / GitHub Actions ได้ตรง — pass/fail test ใน CI pipeline
  • ดู App Service, AKS, Azure Monitor metric ในหน้าเดียวกับ load test result
  • เหมาะกับ organization ที่ใช้ Azure ecosystem อยู่แล้ว

AWS Distributed Load Testing

Paid (AWS infrastructure cost) Platform: AWS (Fargate + CloudWatch)

ใช้ทำอะไร: deploy Taurus/JMeter containers บน AWS Fargate เพื่อรัน distributed load test

ทำไมองค์กรเลือกใช้:

  • เหมาะกับ AWS ecosystem — ดู CloudWatch metric ควบกับ load test result
  • scale worker container ได้ตามต้องการ ไม่มีขีดจำกัดคงที่
6. API Testing & Exploration

เครื่องมือกลุ่มนี้ใช้สำรวจ API, ทดสอบ manual, และเขียน automated functional test ก่อนทำ load test

Postman

Free + Paid Platform: Desktop, Web

ใช้ทำอะไร: ส่ง HTTP request แบบ manual, เขียน test script ด้วย JavaScript, สร้าง Collection แชร์กันในทีม

ทำไมองค์กรเลือกใช้:

  • ใช้ง่ายที่สุดสำหรับ explore API ครั้งแรก — ไม่ต้องเขียน code
  • Postman Collection Runner รัน functional test ทั้ง collection ได้อัตโนมัติ
  • แชร์ Collection ระหว่างทีม dev, QA, perf test ได้ — ทุกคนใช้ request เดียวกัน
  • Newman CLI รัน Collection ใน CI/CD ได้โดยไม่ต้องเปิด GUI

ใช้เมื่อ: explore API ครั้งแรก, debug request, สร้าง functional test ก่อน load test

curl / httpie

Open Source Free Platform: Terminal (ทุก OS)

ใช้ทำอะไร: ส่ง HTTP request จาก terminal โดยตรง — เร็ว, ไม่ต้องติดตั้ง GUI

ทำไมองค์กรเลือกใช้:

  • curl มีในทุก Unix system — ใช้ได้ใน CI/CD, Docker, production server
  • httpie (http command) output อ่านง่ายกว่า curl มาก — highlight JSON อัตโนมัติ
  • เหมาะสำหรับ quick sanity check และ scripting ใน shell
7. Common Tool Stacks ในองค์กรจริง

องค์กรมักใช้เครื่องมือหลายตัวร่วมกัน ด้านล่างนี้คือ stack ที่พบบ่อยในไทยและต่างประเทศ

Stack A: JMeter + InfluxDB + Grafana (Classic Stack)

พบบ่อยในองค์กรที่ใช้ JMeter มาก่อน และต้องการ real-time dashboard

JMeter (ยิง load)
  └─ Backend Listener → InfluxDB (เก็บ metric แบบ real-time)
                          └─ Grafana Dashboard (แสดงกราฟ real-time)

หลังรัน:
JMeter → สร้าง HTML report จาก .jtl file
  • เหมาะกับ: QA team ที่ใช้ JMeter อยู่แล้ว
  • เริ่มต้น: ติดตั้ง InfluxDB + Grafana ด้วย Docker Compose
  • import dashboard สำเร็จรูปจาก Grafana.com ID: 1152 (JMeter dashboard)

Stack B: k6 + Prometheus + Grafana (Modern DevOps Stack)

พบบ่อยในทีม DevOps / SRE ที่ใช้ Kubernetes และ Prometheus อยู่แล้ว

k6 (ยิง load)
  └─ --out prometheus-rw → Prometheus (scrape metric)
                             └─ Grafana Dashboard (แสดงกราฟ)

หรือ:
k6 → --out influxdb → InfluxDB → Grafana
  • เหมาะกับ: dev/DevOps ที่เขียน JavaScript ได้, ใช้ Kubernetes
  • เริ่มต้น: k6 run --out prometheus-rw=http://localhost:9090/api/v1/write script.js
  • import dashboard จาก Grafana.com ID: 19665 (k6 Prometheus dashboard)

Stack C: JMeter + BlazeMeter Cloud (Enterprise Load)

พบบ่อยในองค์กรที่ต้องการ load สูง (หลักพัน VU) โดยไม่ต้องตั้ง infrastructure เอง

JMeter .jmx (script บนเครื่อง dev)
  └─ upload → BlazeMeter Cloud
                └─ รัน distributed จาก multiple regions
                └─ real-time dashboard + report PDF
  • เหมาะกับ: ต้องการ 500–10,000 VU, global test
  • เริ่มต้น: สมัคร BlazeMeter free tier (50 VU, 10 min/test)

Stack D: k6 + Grafana Cloud + APM (Full Observability)

พบบ่อยใน modern cloud-native organization

k6 Cloud (load generation)
  └─ Grafana Cloud (load test dashboard)

Application (รัน under test)
  └─ OpenTelemetry → Grafana Tempo (traces)
  └─ prom-client → Prometheus → Grafana (metrics)

9. How To Choose
ถ้าทีมของคุณแนะนำ Load Toolแนะนำ Monitoring Stack
เป็น QA ที่ไม่ถนัด code, เริ่มต้น performance testing JMeter (GUI, plugin, community) JMeter HTML report → ค่อยเพิ่ม InfluxDB + Grafana
เป็น developer ที่ถนัด JavaScript, ใช้ CI/CD k6 (code-friendly, CI-ready) k6 + Prometheus + Grafana
เป็น Java/Kotlin developer, ต้องการ built-in report Gatling (Maven/Gradle plugin) Gatling HTML report → ค่อยเพิ่ม Grafana
ถนัด Python, ต้องการ distributed บน Kubernetes Locust Locust + Prometheus + Grafana
ต้องการ cloud scale (1,000+ VU), ไม่อยาก manage infra BlazeMeter (JMeter cloud) หรือ k6 Cloud Built-in cloud dashboard
ใช้ Azure / AWS ecosystem Azure Load Testing หรือ AWS DLT Azure Monitor / CloudWatch
ต้องการ full observability (traces + metrics + logs) k6 หรือ JMeter OpenTelemetry + Grafana Stack (Tempo, Prometheus, Loki)
