Read The Result

หลังจากรัน test เสร็จ อย่าดูแค่ว่า request ผ่านหรือไม่ ให้ดู 4 อย่างพร้อมกัน: transaction time, error rate, throughput, และ traffic mix

What To Open In JMeter

ComponentUse It To CheckWhy It Matters
View Results Treeresponse จริงของแต่ละ requestใช้ debug เมื่อ request fail, variable ไม่ถูก extract, หรือ body/header ผิด
Summary Reportaverage, min, max, error %, throughputใช้ดูภาพรวมเร็ว ๆ ว่ารอบ test ผ่าน SLA ขั้นต้นหรือไม่
Aggregate Reportmedian, 90%, 95%, 99%ใช้ตัดสิน SLA เพราะ percentile สำคัญกว่าค่าเฉลี่ย
Transaction Controller parent sampleเวลารวมของ flowใช้ตอบลูกค้าว่า user journey ทั้งก้อนเร็วพอหรือไม่
Backend Listener (ถ้ามี)metric ต่อเนื่องระหว่างรันนาน ๆใช้ดู drift ใน load/endurance test

What To Look At First

  1. ดู Error % ก่อน ถ้ายังมี error สูง แปลว่ายังไม่ผ่านก่อนดู latency
  2. ดู 90%, 95%, 99% ใน Aggregate Report
  3. ดู parent sample ของ Transaction Controller ว่า flow รวมใช้เวลาเท่าไร
  4. ดู Throughput Controller ว่า sample count ของ cart flow ใกล้กับ % ที่ตั้งไว้หรือไม่
  5. ถ้ามี If Controller ให้เช็กว่า order status ถูกเรียกเฉพาะตอนมี orderId จริง
สำหรับตัวอย่าง SLA statements, test type decision, และ run order — ดูที่ Test Types

Proof Of Concept You Can Copy And Paste

ถ้าต้องการทำ proof of concept แบบเร็ว ให้คัดลอก statement, structure, และค่าตั้งต้นนี้ไปใช้ก่อน

POC SLA Statement

Customer SLA Statement
"Under normal business load, the demo browse flow must complete with p95 below 800 ms,
and the Add And Checkout transaction must complete with p95 below 1500 ms,
with error rate below 1%.
Around 40% of browse sessions are expected to continue to cart and checkout."

POC Test Type Decision

Recommended test type: Load Test

Reason
- The statement talks about normal business load
- It includes a browse flow target
- It includes a checkout transaction target
- It includes a traffic mix target of 40%

POC JMeter Structure

Test Plan
├─ HTTP Request Defaults
├─ Thread Group
│  ├─ Transaction Controller - Browse Flow
│  │  ├─ HTTP Request - demo context
│  │  │  └─ JSON Extractor
│  │  ├─ HTTP Request - demo dashboard
│  │  ├─ HTTP Request - demo search
│  │  └─ HTTP Request - product details
│  ├─ Throughput Controller - Cart Flow (40%)
│  │  └─ Transaction Controller - Add And Checkout
│  │     ├─ HTTP Request - add to cart
│  │     └─ HTTP Request - checkout
│  │        └─ JSON Extractor
│  ├─ If Controller - if demoOrderId exists
│  │  └─ HTTP Request - order status
│  ├─ Summary Report
│  └─ Aggregate Report
└─ View Results Tree

POC Starting Values

HTTP Request Defaults
- Protocol: http
- Server: localhost
- Port: 3001

Thread Group
- Number of Threads: 10
- Ramp-Up Period: 5
- Loop Count: 20

Throughput Controller
- Style: Percent Executions
- Percent: 40

Transaction Controller
- Generate parent sample: true

POC JSON Extractor Setup

Under /demo/context
- demoCartId = $.cartId
- demoShopperId = $.shopperId
- demoProductId = $.recommendedProductId
- demoSearchTerm = $.searchTerm

Under /demo/checkout
- demoOrderId = $.orderId

POC Request Bodies

POST /demo/cart/add
{
  "cartId": "${demoCartId}",
  "productId": "${demoProductId}",
  "quantity": 1
}
POST /demo/checkout
{
  "cartId": "${demoCartId}",
  "customerId": "${demoShopperId}"
}

POC Pass Criteria

Pass if:
- Browse Flow p95 < 800 ms
- Add And Checkout p95 < 1500 ms
- Error rate < 1%
- Cart Flow sample count is around 40% of Browse Flow sample count

POC Example Conclusion

Example result
- Browse Flow p95 = 640 ms
- Add And Checkout p95 = 1280 ms
- Error rate = 0.4%
- Browse Flow count = 1000
- Cart Flow count = 401

Conclusion
- Browse Flow passed
- Add And Checkout passed
- Error rate passed
- Traffic mix passed
- This proof of concept meets the sample customer SLA
